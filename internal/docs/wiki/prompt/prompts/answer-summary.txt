## metadata 字段说明
- tags: JSON 数组格式的关键词标签，3-8 个
- quality: 这条回答的质量评分，格式 "X/5"（如 "4/5"）
- author: 回答者名（取自标题破折号之后）
- uncertainties: 回答中不确定或需要核实的信息（可选）
- duration / transcriptQuality / verdict / stars / language: 本条不适用，留空字符串或 0

## 类型约束
以下字段必须是 JSON 数组（不是逗号分隔的字符串）：
- tags: string[]
- summary.keyPoints: string[]
- summary.keyQuotes: string[]

## 摘要质量要求
- overview 必须 3-5 句，包含这条回答的具体论据、数据或例子，不能只说"该回答介绍了XX"
- keyPoints 至少 3 条，每条附带具体数据、例子或细节
- 目标：读者只看摘要就能掌握这条回答的核心论点，无需再打开原文
- **术语保留**：原文中的英文技术术语保留原文，不要意译成模糊描述
- **语言一致性**：正文是哪种语言，摘要就以哪种语言为主
- **客观性标记**：区分「作者声称」和「客观事实」，用「作者认为」「作者举例」等措辞标注

## 各字段输出指导

### summary.detail — 详细摘要
当正文超过 3000 字符时，按「回答者的出发点 → 核心论点 → 论证/举例 → 结论」展开 3-5 句；正文较短可省略。

### summary.keyQuotes — 关键原文引用（JSON 数组）
提取 2-4 条最有代表性的原文引用或数据，标注来源（如「作者指出」「作者举例」）。

## 兜底规则
如果正文是错误页、空壳页面或内容确实无法总结，把 summary.overview 写成对正文实际内容的如实描述并设 confidence 为低值。只有正文完全为空时才返回 topicPath="none"、wikiType="inbox"、needsManualReview=true。
metadata.contentType 如果无法判断默认为 "text"。
